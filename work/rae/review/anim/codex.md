RAE 덱은 **기존 3–4장을 클리커로 진행하는 애니메이션 두 장으로 대체**하는 구성이 좋습니다. 3장은 같은 이미지를 SD-VAE와 RAE가 각각 어떤 DiT 토큰으로 바꾸는지 보여 줍니다. 4장은 RAE latent에서 **복원과 생성의 입력이 어디서 갈라지고, 두 경로에서 무엇을 검증하는지** 보여 줍니다. 발표 분량은 21장·1200초입니다.

### `DeckAnim.define` 계약

```ts
DeckAnim.define(
  name: string,
  factory: (svg: SVGSVGElement, lib: Readonly<AnimLib>) => {
    beats: readonly number[]
    render: (t: number) => void
  }
): void
```

- `name`은 덱 내 고유 키입니다. 빌드가 등록기 → 장면 스크립트 → 덱 초기화 순으로 넣습니다. `factory`는 SVG 인스턴스마다 한 번 호출하고, 그때 요소 참조와 경로 길이를 구합니다.
- `beats`는 **초 단위의 정지 시각 배열**입니다. `[0, 1.4, 3.2]`면 `k=0`이 진입 그림이고, 두 번의 클릭이 각각 `0→1.4`, `1.4→3.2`를 재생합니다. 세 번째 클릭이 다음 슬라이드로 갑니다. 시간은 엄격히 증가하며 마지막 값은 완성 그림의 시각입니다. `render(t)`의 입력 범위는 엔진이 제한합니다. 장면은 바뀌는 속성을 매번 `t`로부터 모두 정하므로 앞으로 재생한 그림과 뒤에서 바로 찾아간 그림이 같습니다.
- 블록 필드는 `type: "animation"`, `name`, `svg`, `script`, `start: 0`, `entry: "manual" | "first-beat"`, `side: [{title, text, provenance}]`, `reveals`, `print: "default" | "expand"`와 선택적 `signature`, `caption`, `cols`입니다. `side[k]`는 `beats[k]`에 대응합니다.
- `lib`는 `node(svg, key)`(해당 SVG 안의 `data-anim-id` 조회), `attrs(el, values)`(허용한 시각 속성 갱신), `clamp01(u)`, `smoothstep(u)`, `progress(t, from, to)`(클램프한 선형 진행률), `lerp(a, b, u)`, `track(points)`(꺾은선의 누적 거리를 미리 계산해 `u∈[0,1]`에서 `[x,y]`를 반환하는 함수 생성)로 시작합니다. 재생과 키 입력은 엔진이 소유합니다. `minimal.html`의 이동·클립 예제와 `techniques.html`의 경로·확대 예제는 이 정도의 도구로 옮길 수 있습니다. `handover/HANDOVER.md` §§2.2–3, `handover/examples/01-minimal/minimal.html` 68–157행, `handover/examples/02-techniques/techniques.html` 142–242행.

### `deck.js` 변경 의사코드

현재 `next()`는 stepper의 단계를 먼저 쓰지만, CSS 전환 중 두 번째 키를 소비하는 분기는 없습니다. `go()`가 전환 클래스를 지우고 요청한 이동을 계속합니다. 애니메이션에는 아래의 재생 중 분기를 명시적으로 넣어야 합니다. `deck.js` 55–112, 185–199, 215–268행.

```text
진입(i, 원인, 명시한 k)
  기존 재생 취소 및 CSS 전환 정리
  일반 슬라이드는 기존 stepper/toggle 경로 사용
  애니메이션은 명시한 k, 역방향 진입이면 마지막 k, 나머지는 start에 seek
  정방향 슬라이드 이동으로 들어왔고 entry가 first-beat이면 구간 0→1 실행
  애니메이션 슬라이드 전환에서는 CSS 교차 페이드 생략

다음
  재생 중이면 목표 정지점으로 즉시 이동하고 이 입력을 소비
  정지 중이고 다음 beat가 있으면 그 구간만 실행
  마지막 beat이면 다음 슬라이드 진입

이전
  재생 중이면 진행 중인 구간의 출발 정지점으로 돌아가고 이 입력을 소비
  정지 중이고 k > 0이면 k−1로 즉시 이동
  k = 0이면 이전 슬라이드의 마지막 상태로 진입

구간 실행
  목표 beat의 옆 글 표시. rAF 하나로 현재 슬라이드만 갱신
  끝에 도달하면 정확한 끝 시각을 그리고 k·해시·안내 확정
  모션이 꺼져 있으면 같은 확정 절차를 즉시 실행
  이동·해시 점프·G 진입 시 이전 프레임 콜백 취소
```

- **해시.** 애니메이션은 `#/n/k`로 씁니다. 슬라이드 번호 `n`은 1부터, beat `k`는 0부터입니다. `#/n`은 시작점의 별칭입니다. 해시 진입·새로고침은 해당 정지점에 바로 도착합니다. 해시 전체 형식을 검사하고 숫자는 범위에 맞추며, beat마다 브라우저 히스토리를 쌓지 않는 기존 `replaceState` 방식을 유지합니다. 자리 이동 키의 `event.repeat`은 무시합니다.
- **개요 G.** 재생 중이면 목표 beat를 확정하고 `(슬라이드, beat)`를 저장합니다. 썸네일은 완성 그림으로 표시하고 선택 위치는 별도로 관리합니다. G/Esc로 닫으면 저장한 beat로 복귀합니다. Enter나 클릭으로 다른 장을 열면 그 장의 시작 상태에 정지합니다.
- **모션과 내보내기.** `still()`의 쿼리·덱 설정·OS 우선순위를 재사용합니다. `window.__deck.animBeats(i)`는 정지 시각 배열을 반환하고, `window.__deck.seekAnim(i, {beat: k})`와 `seekAnim(i, {time: t})`는 재생과 주소 갱신 없이 즉시 그립니다. `i`는 기존 QA 훅처럼 0부터 셉니다. 중간 시각을 찍을 때는 실제 재생과 같은 목표 beat의 옆 글을 사용합니다. PDF는 beat 훅만 사용합니다. 장면 초기화나 렌더가 실패하면 빌드가 넣은 완성 SVG와 옆 글을 복구하고 클리커 이동을 계속합니다. `deck.js` 20–33, 250–268행, `handover/HANDOVER.md` §§4, 6.

### 빌드·QA 게이트

- **구조와 시간.** 애니메이션 장에 `toggle`이나 `stepper`를 함께 두거나, 등록 키·SVG 참조가 중복 또는 누락되면 실패시킵니다. 초기 기준은 **정지점 3–4개, 재생 구간 2–3개, 구간당 1–3초**입니다. `first-beat`에는 첫 구간 상한 1.2초를 적용합니다. `side` 개수와 각 beat의 출처, `reveals`, `start`, `print`, 덱 전체 상호작용 수와 signature 수도 검사합니다. `interaction-rules.md` 7–19행, `block-vocabulary.md` 12–26, 54–60행.
- **그림과 결정성.** 첫 그림에는 발표자가 첫 문장을 말할 수 있는 대상과 라벨이 있어야 합니다. 마지막 그림은 자체로 읽혀야 하며 SVG 원본과 일치해야 합니다. 브라우저에서 빌드한 결과로 순방향·역방향·임의 순서의 `seek` 결과를 대조합니다. 정지점과 구간의 25·50·75% 프레임에서 잘림·겹침을 검사합니다. SVG `id`, 마커, 클립 참조에는 인스턴스별 접두어를 붙입니다. 원격 리소스, SVG 내 스크립트, 장면 자체의 타이머나 반복 재생은 빌드에서 거릅니다. `handover/HANDOVER.md` §§2.1, 7, 8.3.
- **투사 품질.** SVG 글자와 옆 글 모두 무대 기준 24px 하한을 적용합니다. 이 두 장의 주요 라벨은 32–36px로 잡습니다. 글꼴은 실제 빌드 번들과 Chromium이 그린 글리프로 확인합니다. `context.md` 21–22행의 Pretendard 계열과 `design-system-deck.md` 13–17행의 Geomini/Gmarket Sans 명세가 다르므로, 제공 자료만으로 실제 번들 글꼴 이름을 확정할 수 없습니다. 초기 구현에서는 매 프레임 갱신하는 SVG 필터를 금지하고 이동·클립·불투명도로 구현합니다. `design-system-deck.md` 9–17, 29–46행, `handover/HANDOVER.md` §3.
