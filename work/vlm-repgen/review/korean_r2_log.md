사용자: "단어선택과 어투에 AI slop이 너무 심해서 무슨 내용인지 이해를 못하겠다(특히 16, 20번)."
로컬 스킬(1.3.0)이 GitHub 최신판과 같음을 확인하고 적용했다. 교정표는 `korean_r2.md`(74행).

## 진단
검사기 후보는 적었다(연결어미 뒤 쉼표 41건은 대부분 정상). 문제는 표면 문형이 아니라 덱 작성자가 만든
압축 명사구와 정의 없이 쓴 말이었다(L3-3 과압축 명사구, L1-11 대상 불명, L1-8 반복 어휘).

| 쓰던 말 | 문제 | 바꾼 말 |
|---|---|---|
| 통제 비교 (18회) | 정의 없이 반복 | 비교 실험. 14번에서 "한 가지만 바꾸고 나머지는 같게 둔 실험"으로 정의 |
| 대안 설명 / 지움·일부·남음 | 덱이 만든 분류어, 무엇을 지웠는지 안 보임 | 질문형 "재구성을 잘하는 latent라서?" + 결론 "아니다·일부만 확인·가능성 남음·확인 안 됨" |
| 공유의 몫 / latent 자체의 몫 | 압축 명사구 | VLM과 같은 토큰을 쓴 효과 / AF latent 자체가 학습하기 쉬운 효과 |
| VLM 조건, LLM 조건 | 누가 무엇에 조건을 주는지 생략 | VLM이 조건을 줄 때, 텍스트 전용 LLM이 조건을 줄 때 |
| 이해 입력, 생성 latent | 압축 | VLM이 읽는 이미지 입력, 생성 모델이 만드는 latent |
| 0.89B 밖의 비용, 시각 경로 | 대상 불명 | VLM 이미지 입력 모듈 교체, pixel decoder, VLM마다 tokenizer 재학습 |
| 공유 표현의 생성 이득은 무엇에서 오나 | 과압축 질문 | AF 토큰으로 생성이 잘되는 이유는 무엇인가 |
| 생성 stream | 논문 용어지만 처음 나올 때 뜻 없음 | 유지, 2·5·9번에 "생성을 맡는 별도 transformer" |

## 보존 확인
- `apply_text_edits.py`가 숫자가 바뀐 5행을 거부했다. 모두 덱이나 논문에 이미 있는 값을 문장에 넣은 경우라
  직접 반영했다: 10번 대본 "256 해상도"(Table 7), 16번 제목 "50K step", 16번 표 "2B", 16번 대본 "9B·2B",
  20번 대본 "50K step".
- 저자 해석·발표자 판단 표시, "약"(곡선 값), 단위, 모델 이름은 그대로 두었다.
- 16번 표는 폭에 맞추느라 칸 문구를 더 줄였다("2B VAE 실험 없음"은 실험 칸 "2B 백본(AF만)"으로).
- 5번 SVG의 두 질문도 beat 문구와 같게 다시 만들었다.
