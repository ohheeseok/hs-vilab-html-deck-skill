# 시각 검수: hs-vilab-html-deck 전체 덱 21장 (Self-Flow 논문 리뷰, 20분 세미나)

너는 이 덱의 **시각 검수자**다. 캡처 이미지를 직접 열어 보고 판단한 결과만 출력하라.
덱은 1920×1080 무대를 창 크기에 맞춰 축소·확대하는 HTML 발표자료다. 발표자는 연구실 교수이고 세미나 프로젝터(1024×768일 수 있음)와 노트북에서 쓴다.

## 폴더
- `shots/1920/`, `shots/1024/` — 슬라이드별 캡처 `sNN.png`, 토글 슬라이드는 상태별 `sNN-<state>.png`(6번 4상태, 14번 3상태, 15번 2상태). 1024는 위아래 레터박스. 프로젝터 가독성은 1024로 판단.
- `rules/` — 디자인 규칙(`design-system-deck.md`), 블록(`block-vocabulary.md`), 인터랙션(`interaction-rules.md`). `deck.css`, `deck.json`(내용).

## 다시 논의하지 않는 것
- 확정된 디자인: 흰 바탕 + 2·20번 다크 statement, 하단 진행 표시줄(구간 길이 = 장 수 비례), 표지 구성, 글자 크기 사다리와 24px 하한, eyebrow·그림자·왼쪽 색 띠 금지, 패널 ≤ 2/장.
- 기계 QA 통과 항목(무대 넘침, 띠 이탈, 24px 하한, 대비, 글꼴, 제목 한 줄). 다시 세지 마라.
- 내용의 사실 여부(별도 검증 중). 제목이 결론을 말하지 않는 것은 규칙이다.

## 볼 것
1. 위계: 첫눈에 무엇을 보는가. 그림·표·수치가 슬라이드의 중심으로 읽히는가.
2. 정렬·여백: 왼쪽 기준선, 열 상단, 블록 간격이 슬라이드 사이에 일관적인가. 어색하게 빈 영역(예: 3·19·21번 아래쪽), 몰린 영역.
3. 일관성: 캡션 형식(**Fig. n** + 공백), 표 정렬, deltas, compare 열, 토글 버튼·읽기 칸이 같은 모양인가.
4. 1024×768 가독성: 논문 그림 속 축·범례 글자(4, 6, 13, 15–18번), 표 숫자, 막대 값.
5. 토글: 상태를 바꿀 때 무엇이 바뀌는지 분명한가. 그림 탭(14, 15번)의 그림 크기가 상태마다 들쭉날쭉하지 않은가.
6. 한국어 줄바꿈: 단어 중간 끊김, 한두 글자 고아 줄, 숫자·단위 분리.
7. 다크 슬라이드(2, 20번)의 대비와 위계.

## 출력 (한국어, 1200단어 이내)
- 지적마다 `[A번호] 슬라이드 · P0(오독·발표 불가)/P1(눈에 띄는 결함)/P2(다듬기) · 무엇이 보이는가(1920 좌표) · 왜 문제인가 · 고칠 방법(px, deck.json 필드, 셀렉터)`. 심각도 순.
- 문제 없는 슬라이드는 묶어서 "통과: …".
- 마지막에 "가장 먼저 고칠 5가지".
