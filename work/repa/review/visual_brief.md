# 시각 검수: hs-vilab-html-deck 21장 (REPA 논문 리뷰, 20분 세미나)

너는 이 덱의 **시각 검수자**다. 캡처 이미지를 직접 열어 보고 판단한 결과만 출력하라.
덱은 1920×1080 무대를 창 크기에 맞춰 축소·확대하는 HTML 발표자료다. 발표자는 연구실 교수이고 세미나 프로젝터(1024×768일 수 있음)와 노트북에서 쓴다. 이 스킬로 만든 두 번째 논문 덱이다.

## 폴더
- `shots/1920/`, `shots/1024/` — 슬라이드별 캡처 `sNN.png`. 토글 슬라이드는 상태별 `sNN-<state>.png`(9번 3상태: probe·align·fidacc, 12번 3상태: parrot·balloon·burger). 6번은 stepper(다음 키로 도식이 한 단계씩 드러남)이고, 캡처는 첫 단계와 `s06-step1`…`s06-step4`. 1024는 위아래 레터박스. 프로젝터 가독성은 1024로 판단.
- `rules/` — 디자인 규칙(`design-system-deck.md`), 블록(`block-vocabulary.md`), 인터랙션(`interaction-rules.md`). `deck.css`, `deck.json`(내용), `repa_stepper.svg`(6번 도식 원본).

## 다시 논의하지 않는 것
- 확정된 디자인: 흰 바탕 + 2·20번 다크 statement, 회색 바탕(wash)은 차트·표 슬라이드, 하단 진행 표시줄(구간 길이 = 장 수 비례), 표지·ending 구성, 글자 크기 사다리와 24px 하한, eyebrow·그림자·왼쪽 색 띠 금지, 패널 ≤ 2/장.
- 기계 QA 통과 항목(무대 넘침, 띠 이탈, 블록 겹침, 24px 하한, 대비, 글꼴, 제목 한 줄). 다시 세지 마라.
- 내용의 사실 여부(별도 검증 중). 제목이 결론을 말하지 않는 것은 규칙이다.
- 논문 그림은 원본 크롭이다. 그림 안의 글자 크기는 원본 비율을 따른다 — 문제는 "슬라이드에서 그림을 더 크게 보일 수 있는데 작게 두었는가"다.

## 볼 것
1. 위계: 첫눈에 무엇을 보는가. 그림·표·수치가 슬라이드의 중심으로 읽히는가.
2. 정렬·여백: 왼쪽 기준선, 열 상단, 블록 간격이 슬라이드 사이에 일관적인가. 내용이 적은 슬라이드(3, 7, 8, 11, 15, 16, 19)는 본문을 세로 가운데에 두었다 — 그게 어색하지 않은가. 남은 어색한 빈 영역, 몰린 영역.
3. 6번 stepper: 단계마다 새로 드러나는 것이 분명한가. 도식 안 글자·화살표·강조(주황 테두리 patch)가 읽히는가. 마지막 단계(추론)에서 반투명 덮개로 학습 경로를 가린 표현이 이해되는가. 오른쪽 단계 목록과 도식이 맞물리는가.
4. 일관성: 캡션 형식(**Fig. n** + 공백), 표 정렬·강조 행, deltas, 토글 버튼·읽기 칸이 같은 모양인가.
5. 1024×768 가독성: 논문 그림 속 축·범례 글자(4, 5, 9, 14, 17, 18번), 표 숫자. 특히 5·18번처럼 그림 두 개를 나란히 둔 곳.
6. 토글: 상태를 바꿀 때 무엇이 바뀌는지 분명한가. 그림 탭(9, 12번)의 그림 크기가 상태마다 들쭉날쭉하지 않은가. 12번 합성 그림(행 라벨 + 열 머리 + 클래스 하나)이 원 그림처럼 읽히는가.
7. 한국어 줄바꿈: 단어 중간 끊김, 한두 글자 고아 줄, 숫자·단위 분리.
8. 다크 슬라이드(2, 20번)의 대비와 위계. 20번 토론 네 항목이 발표 중에 읽힐 분량인가.

## 출력 (한국어, 1200단어 이내)
- 지적마다 `[A번호] 슬라이드 · P0(오독·발표 불가)/P1(눈에 띄는 결함)/P2(다듬기) · 무엇이 보이는가(1920 좌표) · 왜 문제인가 · 고칠 방법(px, deck.json 필드, 셀렉터)`. 심각도 순.
- 문제 없는 슬라이드는 묶어서 "통과: …".
- 마지막에 "가장 먼저 고칠 5가지".
