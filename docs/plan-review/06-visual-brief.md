# 시각 검수 요청: hs-vilab-html-deck 샘플 6장 (Self-Flow 논문 리뷰)

너는 이 덱의 **시각 검수자**다. 코드는 고치지 말고, 캡처 이미지를 직접 보고 판단한 결과만 써라.
덱은 1920×1080 무대를 브라우저 창에 맞춰 축소·확대하는 HTML 발표자료다(PPT 대용). 발표자는 연구실 교수이고, 연구실 세미나 프로젝터(1024×768일 수 있음)와 노트북 화면에서 쓴다.

## 이 폴더에 있는 것 (읽기 전용)
- `shots/1920/` : 1920×1080 캡처. s01 표지, s02 요약(다크), s03-vanilla·s03-dual(같은 슬라이드의 토글 두 상태), s04 T2I 결과 막대, s05 ImageNet 표, s06 정리와 토론(다크).
- `shots/1024/` : 같은 슬라이드를 1024×768 창에서 찍은 것(위아래 레터박스). 프로젝터 가독성은 이걸로 판단하라.
- 캡처는 모션이 끝난 최종 상태다(`?motion=0`). 모션 자체는 평가 대상이 아니다.
- `rules/SKILL.md`, `rules/design-system.md` : 디자인 원천 규칙(hs-vilab-frontend-design).
- `tokens.css`, `deck.css` : 토큰과 엔진 CSS. `deck.json` : 슬라이드 내용. `PLAN.md` : 확정 계획(§10과 끝부분에 최근 변경).

## 이미 확정되어 다시 논의하지 않는 것
- 2·6번 다크 배경(`#12263D`), 3–5번 패널(슬라이드당 ≤ 2), 2·6번 세로 구분선, 표지 가로선+하늘색 막대, 3번 토글 인터랙션, HSU 시그니처 로고(학교 공식 파일).
- 글자 크기 사다리 80/56/48/40/36/32/28/24px, **24px 하한**(무대 기준). eyebrow·대문자 자간 라벨·`A · B · C` 메타 줄·왼쪽 색 띠·그림자 금지.
- 기계 QA는 이미 통과: 무대 넘침, 24px 하한, 대비 4.5 이상(HTML 텍스트), 글꼴, 구역 겹침. 이것들을 다시 세지 말고 **사람 눈에만 보이는 문제**를 찾아라.

## 최근 바뀐 것 (특히 봐 달라)
- 표지(s01): 오른쪽 열에 발표자 이름·소속·행사명·로고. 원 논문 저자·소속은 부제 아래 회색 두 줄로 내림. 그림은 남은 높이에 맞춰 줄어듦.
- 3번 Dual 상태: 패널 안 설명 줄간격을 1.55→1.45로 줄여 하단 그림 설명이 진행 표시줄에 닿지 않게 함.

## 볼 것
1. **위계**: 슬라이드마다 첫눈에 무엇을 보게 되는가. 핵심 문장(`message`)과 근거(그림·표·수치)가 그 순서로 읽히는가.
2. **정렬·여백 리듬**: 왼쪽 기준선, 열 상단 정렬, 블록 간격이 슬라이드 사이에 일관적인가. 어색하게 빈 영역이나 몰린 영역.
3. **일관성**: 같은 종류의 요소(캡션, 수식, 범례, 델타 수치, 패널)가 슬라이드마다 같은 모양인가.
4. **1024×768 가독성**: 표의 숫자, 막대 값 라벨, 원본 그림 속 축 라벨·글자, 수식 아래첨자가 읽히는가. 읽히지 않으면 어떤 요소인지 정확히.
5. **다크 슬라이드**: 프로젝터에서 대비·계층이 무너지지 않는가.
6. **표지**: 발표자 블록과 논문 크레딧의 위계, 그림과 오른쪽 열의 균형, 로고 크기.
7. **한국어 줄바꿈**: 단어 중간 끊김, 한 글자 고아 줄, 숫자·단위 분리.

## 출력 형식 (한국어, 1000단어 이내)
- 지적마다 한 항목: `[ID] 슬라이드 · 심각도(P0 발표 불가/오독, P1 눈에 띄는 결함, P2 다듬기) · 무엇이 보이는가(대략 위치를 1920 좌표로) · 왜 문제인가(규칙 근거가 있으면 조항) · 고칠 방법(구체 값: px, 색 hex, 대상 셀렉터나 deck.json 필드)`.
- 심각도 순으로 정렬. 확신이 없으면 "추정"이라고 적어라. 문제 없다고 보는 슬라이드는 한 줄로 "통과"라고 써라.
- 마지막에 "가장 먼저 고칠 3가지"를 한 줄씩.
