## v2에서 수정할 결정

1. **발표 화면에 `N`으로 노트를 띄우면 청중에게도 대본이 보일 수 있다.** v1에서는 발표용 HTML에서 노트와 조작 큐를 빼고, 별도로 여는 `script.html`에만 둔다.
2. **`postMessage`의 ‘origin 무관’은 후속 구현 사양으로 위험하다.** v2 발표자 창을 구현할 때는 두 창을 같은 로컬 HTTP 출처에서 열고, 수신 시 발신 출처와 창 참조를 모두 확인한다.
3. **조작 직후 포커스를 덱으로 돌리면 키보드 사용자가 같은 컨트롤을 연속 조작하기 어렵다.** 포커스는 유지하고, 컨트롤이 사용하는 키만 슬라이드 전환에서 제외한다. `Esc`로 무대에 돌아오게 한다.
4. **상태별 출처를 기록해도 `print: "default"`가 비교의 핵심 근거를 숨길 수 있다.** 결론에 필요한 상태는 인쇄용 정적 비교에 모두 포함하고, 예상 페이지 수는 인쇄 목록에서 산출한다. 상태 페이지 \(k\)장이 원래 한 장을 대체하면 순증은 \(k-1\)장이다.
5. **SVG의 `fill` 일괄 치환은 의도한 색도 바꿀 수 있다.** SVG를 파싱해 수식 기본 전경색만 `currentColor`로 바꾸고, 이름을 바꾼 ID를 가리키는 내부 참조도 함께 갱신한다.
6. **무대의 24px 하한과 그림 폭 90%만으로는 축소 후 판독성을 판정할 수 없다.** 1024×768 레터박스에서 24px는 화면상 12.8 CSS px에 해당한다. 최소 지원 화면의 스크린샷에서 표 숫자와 원본 그림 속 라벨까지 읽을 수 있는지 확인한다.
7. **대표 인터랙션을 필수로 해석하면 짧은 덱에서 20% 상한과 충돌한다.** 대표는 0–1개로 두고 전체 상한은 내림으로 명시한다. 6장 샘플에는 한 개만 들어간다.
8. **agy 비전 검토가 필수면 해당 도구에 연결할 수 없는 환경에서 독립 실행이 막힌다.** 로컬에서 검토할 스크린샷을 생성하고, 실제 시각 검토 수행 여부를 납품 기록에 남긴다.

## 열람 모드 최종 입장

v1에 **320 CSS px부터 재배치되는 읽기 모드**를 넣는다. 발표 모드는 16:9 고정 무대로 유지하고, 같은 `deck.json`에서 제목·본문·수식·그림·출처와 결론에 필요한 비교 상태를 세로 흐름의 HTML로 생성한다. 발표 모드는 고정 좌표와 넘침을, 읽기 모드는 좁은 폭의 줄바꿈과 읽기 순서를 각각 검증한다. PDF는 페이지 구성을 보존하는 배포본으로 둔다.

## agy 의견 중 반대하는 부분

- **클리커가 `PageDown`과 `ArrowRight`만 보낸다는 전제**는 장비 정보 없이 확정할 수 없다. 기본 키 매핑을 명시하고, 현장에서 쓸 장비가 정해지면 해당 장비로 검증한다.
- **KaTeX 폴백을 v1에 번들하자는 제안**은 수식 렌더링 경로를 두 개로 늘린다. 두 경로의 출력을 검증할 범위가 정해질 때까지 TeX 의존성을 사전 점검에서 명시한다.

## 첫 샘플 6장

**3장**은 토큰별 시간 배정의 차이를 보여주는 `toggle`과 그 차이를 읽는 데 필요한 식 한 개로 줄인다. **4장**은 핵심 지표 하나를 정적 차트로 보여준다. **5장**은 표나 정성 그림 중 앞 장에서 답하지 못한 질문에 답하는 자료 하나를 크게 싣는다. Self-Flow 원문은 대조하지 않았으므로 제안된 그림·표·식 번호와 teacher의 시간 표기는 미확인이다.
