### 1. v2에서 여전히 틀렸거나 위험한 결정과 대안

1. **클리커 포커스 강제 복귀와 `Space` 충돌**
   - 위험: 조작 직후 포커스를 덱으로 회수하면 키보드·스크린리더 사용자의 반복 조작 맥락이 끊긴다. 반대로 클릭 후 버튼에 포커스가 남으면 다음 `Space`가 슬라이드 이동 대신 버튼을 재실행한다.
   - 대안: `PageDown`/`PageUp`/`→`/`←`을 전역 진행 키로 두고(방향키를 쓰는 위젯에 키보드 포커스가 있을 때만 예외), 마우스 클릭 시에만 포커스를 해제한다. `Space`는 버튼 포커스 시 기본 동작에 맡긴다.

2. **`document.fonts` 글리프 검증 착각과 `file://` 폰트 리스크**
   - 위험: 표준 `document.fonts` API는 폰트 로드 여부만 알려주며 한글·라틴 글자의 실제 폴백 폰트는 판별하지 못한다. 또 `file://` 로컬 `@font-face`의 CORS 차단 범위는 브라우저·버전별 편차가 있어(최신 Windows Chromium 동작은 실측 전 불확실) 사후 QA로 미루면 위험하다.
   - 대안: 글리프 검사는 Playwright Chromium CDP(`CSS.getPlatformFontsForNode`, Windows 폴백 보고 정밀도는 실측 확인 필요)를 쓰고, `./assets/` 하위 경로의 Windows `file://` 직열기 스모크 테스트를 1단계로 앞당긴다.

3. **표 본문 24px 하한과 그림 폭 90% 규칙의 기계적 이식**
   - 위험: 1920×1080의 24px을 1024×768 레터박스(배율 0.533)로 줄이면 12.8px이 되어 표 판독이 어렵다. 또 HTML `object-fit: contain`에서는 세로형 그림이 높이 제약으로 폭 90% 미만이 되는 정상 사례가 많아 오탐이 속출한다.
   - 대안: 표 본문 하한을 28px(캡션·출처만 24px)로 높이고, 그림 축소 검사는 제약 축 기준(`max(렌더폭/슬롯폭, 렌더높이/슬롯높이) >= 0.85`)으로 바꾼다.

4. **v1 범위 과다와 `N` 오버레이 노출 위험**
   - 위험: v1에 `metricSwitch`·`slider`·다크모드(`T`)·`print: "expand"`까지 넣으면 QA 조합이 폭증하고, `expand`는 PDF 쪽 번호와 슬라이드 번호를 어긋나게 한다. 같은 창 `N` 오버레이는 화면 공유 중 오타로 대본이 노출된다.
   - 대안: v1은 라이트 단일 테마 + `toggle`/`stepper` 2종으로 줄이고(`metricSwitch`·`slider`·다크모드는 v2), `expand` PDF는 `7a`/`7b` 하위 표기로 번호를 맞춘다. 실전 대본은 별도 창 `script.html`을 기본으로, `N` 오버레이는 `?notes=1` 리허설 옵션으로 잠근다.

### 2. "열람 모드 미결정"에 대한 최종 입장

Claude의 v1 범위(고정 무대 + 배포용 PDF)에 동의하되, v1.1에서 같은 `index.html`에 320px 반응형 읽기 모드를 덧붙이는 방향은 반대한다. 16:9 고정 무대는 발표 도구이자 시각 QA의 단일 진실 원천으로 유지하고, 모바일·200% 확대·무스크립트 열람은 같은 `deck.json`에서 시맨틱 문서형 `handout.html`(또는 `script.html` 확장)을 별도 생성해 해결해야 한다. v1에서는 `index.html`에 `<noscript>` 안내와 PDF/`script.html` 링크만 두면 무대 QA를 해치지 않고 최소 접근성 경로를 확보할 수 있다.

### 3. codex 의견 중 반대하는 항목

- **같은 `index.html`에 320px 반응형 통합**: 16:9 무대 DOM(고정 비율 격자·SVG 도식)과 320px 세로 문서는 레이아웃 계약이 다르다. 한 파일에 묶으면 무대 수정마다 읽기 모드 회귀가 생기고 QA 조합이 폭증하므로, IR 기반 별도 HTML 생성이 맞다.
- **무스크립트(JS off)를 `index.html`의 v1 필수 QA 게이트로 지정**: 인터랙티브 덱이 `index.html` 자체로 JS 차단을 통과하려면 정적 폴백 DOM을 중복 마크업해야 해 인쇄·스크린리더와 충돌하기 쉽다. 무스크립트 열람은 PDF나 정적 `handout.html`로 책임을 분리해야 한다.
